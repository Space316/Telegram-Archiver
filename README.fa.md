## 📖 این پروژه چیست؟

`telegram_archiver.py` یک ابزار تعاملی ترمینالی در یک فایل است که روی [Telethon](https://docs.telethon.dev/) ساخته شده است.
با **اکانت شخصی خودتان** (نه ربات) وارد می‌شود، گروه‌ها و کانال‌هایتان را در یک منوی مرتب نشان می‌دهد، یک چت **هم‌نوع و هم‌نام** می‌سازد و تمام تاریخچه را پیام‌به‌پیام و به ترتیب اصلی داخل آن کپی می‌کند.

کاربردهای رایج: پشتیبان‌گیری از چتی که ممکن است دسترسی‌اش را از دست بدهید، مهاجرت یک جامعه، یا آرشیو کردن یک گروه بزرگ تاپیک‌دار (حتی تاپیک به تاپیک).

<summary><b>تازه‌کارید؟ آن دو خط venv برای چیست؟</b></summary>

دستور `python3 -m venv .venv` یک نسخهٔ جدا و ایزولهٔ پایتون در پوشهٔ مخفی `.venv` کنار پروژه می‌سازد و `source .venv/bin/activate` ترمینال را به آن محیط منتقل می‌کند. از آن به بعد، هر `pip install` داخل همان پوشه نصب می‌شود و نه روی پایتون سیستم؛ پس این پروژه هرگز با پروژه‌های دیگر تداخل پیدا نمی‌کند (بعضی توزیع‌های لینوکس اصلاً اجازهٔ نصب سراسری نمی‌دهند و خطای `externally-managed-environment` می‌دهند).

وقتی فعال باشد، ابتدای خط ترمینال `(.venv)` نوشته می‌شود. در هر ترمینال جدید باید دوباره خط `activate` را بزنید. برای پاک کردن همه‌چیز، کافی است پوشهٔ `.venv` را حذف کنید. این پوشه در `.gitignore` هست پس روی گیت‌هاب آپلود نمی‌شود.

این مرحله اختیاری است — فقط `pip install -r requirements.txt` هم کار می‌کند.

## 🔑 گرفتن API ID و API HASH

1. به **https://my.telegram.org** بروید و با شمارهٔ موبایلتان وارد شوید
2. بخش **API development tools** را باز کنید و یک اپ (با هر نامی) بسازید
3. مقادیر `api_id` و `api_hash` را کپی کنید

سپس به **یکی** از این روش‌ها واردشان کنید (اولین روشی که پیدا شود برنده است):

</div>

```bash
# 1) متغیرهای محیطی
export TG_API_ID=123456
export TG_API_HASH=abcdef0123456789abcdef0123456789
```

```bash
# 2) فایل config.py کنار اسکریپت (روش معمول)
cp config.example.py config.py
nano config.py
```

<div dir="rtl" align="right">

> 3) یا فقط اسکریپت را اجرا کنید — در اجرای اول خودش می‌پرسد و پیشنهاد می‌دهد یک `config.py` خصوصی (با دسترسی 600) برایتان بسازد.

> ⚠️ **فایل `config.py` عمداً در `.gitignore` قرار دارد. هرگز این فایل یا فایل‌های `*.session` را کامیت نکنید.**

## ▶️ نحوهٔ اجرا

</div>

```bash
python3 telegram_archiver.py
```

<div dir="rtl" align="right">

همین یک دستور کافی است — هیچ فلگ و آرگومان خط فرمانی وجود ندارد؛ همهٔ انتخاب‌ها از طریق منوهای تعاملی انجام می‌شود و کافی است به سؤال‌ها جواب بدهید.

### اجرای اول

ابتدا یک **نام برای این اکانت** (هر برچسبی که دوست دارید، مثلاً `main`)، سپس **شمارهٔ موبایل**، **کد ورود** تلگرام و در صورت فعال بودن، **رمز دومرحله‌ای** پرسیده می‌شود. سشن در `accounts/<name>.session` ذخیره می‌شود، پس از اجرای دوم به بعد مستقیم وارد منو می‌شوید.

قبل از نمایش منو، خلاصهٔ تنظیمات و فضای آزاد دیسک در مسیر `DOWNLOAD_DIR` چاپ می‌شود — برای اطمینان از فعال بودن درایو ماونت‌شده مفید است.

### منوی اصلی

</div>

```
◆ M A I N   M E N U ◆
        account main

» 📦  Pick a group/channel to copy
  👤  Copy only one person's messages from a topic
  🔁  Retry failed messages
  🧹  Reset a chat's progress
  🔄  Switch account
  ❌  Exit
```

<div dir="rtl" align="right">

عبارت روبروی `account` فقط همان نامی است که خودتان در اجرای اول برای اکانت انتخاب کرده‌اید.

با کلیدهای ↑ ↓ حرکت کنید و با **Enter** انتخاب کنید. تقریباً هر صفحه یک گزینهٔ **⬅ Back** هم دارد که فقط یک سؤال به عقب برمی‌گردد، نه اینکه کل کار را لغو کند.

| گزینه | چه کاری می‌کند | چه وقت استفاده کنیم |
|---|---|---|
| 📦 **Pick a group/channel to copy** | آرشیو کامل و حالت عادی. چت مقصد را می‌سازد و تاریخچهٔ کل چت (یا تاپیک‌های انتخابی) را کپی می‌کند | نقطهٔ شروع اصلی شما |
| 👤 **Copy only one person's messages from a topic** | مثل بالا، ولی فقط پیام‌های **یک فرستنده**. در لیست، علاوه بر همهٔ اعضا، یک گزینهٔ ویژهٔ *🎭 Anonymous admin* برای پیام‌هایی که به اسم خود گروه ارسال شده‌اند وجود دارد | جدا کردن پست‌های یک نفر، مثلاً نویسندهٔ اطلاعیه‌ها |
| 🔁 **Retry failed messages** | فقط پیام‌هایی که قبلاً ناموفق مانده‌اند (ثبت‌شده در `progress.json`) را دوباره می‌فرستد؛ محافظت ضد تکرار هم فعال است | وقتی اجرا تمام شده ولی چند پیام جا مانده |
| 🧹 **Reset a chat's progress** | رکورد پیشرفت آن چت را پاک می‌کند تا اجرای بعدی از صفر و با **یک چت مقصد تازه** شروع شود. چت قبلی حذف نمی‌شود | وقتی یک اجرا خراب شده و می‌خواهید تمیز شروع کنید |
| 🔄 **Switch account** | برگشت به صفحهٔ انتخاب اکانت؛ هر اکانت سشن و `progress.json` جداگانهٔ خود را دارد | آرشیو با یک اکانت تلگرام دیگر |
| ❌ **Exit** | اتصال را تمیز می‌بندد | پایان کار |

### سؤال‌هایی که حین کپی پرسیده می‌شود

**۱. کدام چت؟** — لیستی قابل جستجو از گروه‌ها و کانال‌ها (کافی است تایپ کنید تا فیلتر شود). سپس خلاصه‌ای از چت انتخابی چاپ می‌شود: فروم هست یا نه، محدودیت ذخیرهٔ محتوا فعال است یا نه، و چند پیام سنجاق‌شده دارد.

**۲. کدام تاپیک‌ها؟** *(فقط فروم‌ها)* — یا **همهٔ تاپیک‌ها**، یا یک لیست چندانتخابی که موردهای دلخواه را تیک می‌زنید. تعداد پیام هر تاپیک کنار نامش نوشته می‌شود.

**۳. چه مقدار کپی شود؟**

| گزینه | معنی |
|---|---|
| 📚 **Everything (full history)** | از اولین پیام تا آخر |
| 🔢 **Only the most recent messages** | یک عدد می‌پرسد، مثلاً `200`. اگر چند تاپیک انتخاب شده باشد، یعنی N پیام آخر **از هر تاپیک** |

**۴. از کجا شروع شود؟**

| گزینه | معنی |
|---|---|
| ⏮ **From the beginning (or where it stopped last time)** | حالت عادی؛ اگر قبلاً قطع شده باشد خودکار ادامه می‌دهد |
| 🔗 **From a specific message — paste its link** | در تلگرام روی پیام راست‌کلیک یا لمس طولانی کنید ← *Copy Message Link*. لینک‌های خصوصی `t.me/c/...` و حتی فقط آیدی پیام هم کار می‌کند. پیام مقصد به عنوان پیش‌نمایش نشان داده می‌شود تا لینک اشتباه فوراً معلوم شود |

**۵. نام فرستنده ابتدای هر پیام اضافه شود؟** — با `Yes` نام فرستندهٔ اصلی در خط اول و به صورت **بولد** نوشته می‌شود (مثل `«علی»`). برای آرشیو تاپیک‌ها خیلی مفید است، وگرنه همهٔ پیام‌ها به اسم شما دیده می‌شوند. در اجراهای چندتاپیکی می‌توانید این را برای هر تاپیک جداگانه تعیین کنید.

بعد از این، کپی شروع می‌شود؛ با نوار پیشرفت زنده برای هر فایل و یک شمارنده مثل `✔ 1,240 copied so far (album of 3, id=90218)`.

### ادامه پس از قطع شدن

پیشرفت در `progress.json` ذخیره می‌شود (به صورت atomic و همراه یک نسخهٔ `.bak`). اگر اجرا قطع شود — Ctrl+C، قطعی اینترنت، بسته شدن لپ‌تاپ — کافی است دوباره اسکریپت را اجرا و همان چت را انتخاب کنید. از پیام بعدی ادامه می‌دهد و نگاشت «آیدی قدیم ← آیدی جدید» را نگه می‌دارد تا ریپلای‌ها سالم بمانند.

## 🖥 اجرای طولانی با tmux (توصیه‌شده روی سرور)

**مشکل چیست؟** وقتی اسکریپت را از طریق SSH اجرا می‌کنید، ترمینال شما پدرِ آن پروسه است. هر لحظه که اتصال SSH قطع شود — قطعی اینترنت، خواب رفتن لپ‌تاپ، بستن پنجره — پروسه هم کشته می‌شود. آرشیو کامل یک گروه بزرگ ممکن است ساعت‌ها طول بکشد، پس این اتفاق زیاد می‌افتد.

**راه‌حل:** `tmux` یک ترمینال را **روی خود سرور** زنده نگه می‌دارد. هر وقت بخواهید به آن متصل می‌شوید تا وضعیت را ببینید، جدا می‌شوید تا در پس‌زمینه ادامه دهد، و بعداً حتی از یک کامپیوتر دیگر دوباره وصل می‌شوید. در تمام این مدت اسکریپت دارد کارش را می‌کند.

(`nohup` و `&` راه‌حل‌های کلاسیک هستند ولی اینجا جواب نمی‌دهند؛ این ابزار تعاملی است و برای منوهایش به یک ترمینال واقعی نیاز دارد.)

### طرز استفاده

</div>

```bash
# 1) یک سشن نام‌دار بسازید
tmux new -s archiver

# 2) داخل آن، اسکریپت را مثل همیشه اجرا کنید
cd ~/Telegram-Archiver
source .venv/bin/activate
python3 telegram_archiver.py

# 3) برای رها کردن در حال اجرا:  Ctrl+b  و بعد  d

# 4) بازگشت در هر زمان دیگر
tmux attach -t archiver
```

<div dir="rtl" align="right">

### دستورهایی که لازم است بدانید

| دستور / کلید | کارکرد |
|---|---|
| `tmux new -s archiver` | ساخت سشنی به نام `archiver` |
| **`Ctrl+b`** و بعد **`d`** | **جدا شدن (detach)** — همه‌چیز در پس‌زمینه ادامه پیدا می‌کند |
| `tmux attach -t archiver` | اتصال دوباره به همان سشن |
| `tmux ls` | لیست سشن‌های در حال اجرا |
| **`Ctrl+b`** و بعد **`[`** | حالت اسکرول — با ↑ ↓ و PageUp لاگ قبلی را بخوانید؛ خروج با `q` |
| `tmux kill-session -t archiver` | حذف سشن (اسکریپت متوقف می‌شود) |

> 💡 کلید `Ctrl+b` در tmux «پیشوند» است: اول آن را می‌زنید و رها می‌کنید، *سپس* کلید دوم را می‌زنید — همزمان نگه نمی‌دارید.

> ⚠️ برای جدا شدن از `Ctrl+b` و `d` استفاده کنید. زدن **`Ctrl+c`** خود اسکریپت را متوقف می‌کند — هرچند به لطف `progress.json` می‌توانید دوباره اجرایش کنید و از همان جا ادامه می‌دهد.

## 🎛 تنظیمات قابل تغییر

همهٔ تنظیمات در بالای فایل `telegram_archiver.py` زیر بخش `# ------------------ settings ------------------` قرار دارند:

| تنظیم | پیش‌فرض | توضیح |
|---|---|---|
| `ADAPTIVE_DELAY` | `True` | تا وقتی تلگرام اعتراض نکند سریع‌تر و با FloodWait کندتر می‌شود |
| `MIN_MESSAGE_DELAY` / `MAX_MESSAGE_DELAY` | `0.3` / `15.0` | کمترین و بیشترین مکث بین پیام‌ها |
| `FAST_TRANSFER` | `True` | دانلود/آپلود چند‌تکه‌ای |
| `TRANSFER_CONNECTIONS` | `8` | تعداد اتصال موازی هر فایل (4 تا 16 منطقی است؛ بیشتر = FloodWait) |
| `PREFER_DIRECT_MEDIA` | `True` | ارسال مدیا با رفرنس به جای دانلود + آپلود |
| `MIN_FREE_DISK_GB` | `3` | اگر فضای آزاد کمتر شد، دانلود متوقف می‌شود |
| `MAX_FILE_SIZE_GB` | `None` | رد کردن فایل‌های بزرگتر از این (`None` = بدون محدودیت) |
| `SPLIT_LONG_TEXT` | `True` | متن‌های بالای 4096 کاراکتر به جای بریده شدن، ادامه ارسال می‌شوند |
| `VERIFY_SENT` | `"media"` | `always` / `media` / `never` — چک کردن رسیدن پیام |
| `DOWNLOAD_DIR` و `ACCOUNTS_DIR` | `downloads` و `accounts` | محل فایل‌های موقت و سشن‌ها |

<details>
<summary><b>💾 فضای دیسک سرور کم است؟ گوگل درایو را با rclone ماونت کنید</b></summary>

اسکریپت هر فایل موقت را بلافاصله پس از آپلود پاک می‌کند، پس فقط به اندازهٔ **یک** فایل فضا لازم دارد. اگر همین هم زیاد است:

</div>

```bash
curl https://rclone.org/install.sh | sudo bash
rclone config                      # یک remote مثلاً به نام gdrive بسازید
mkdir -p ~/gdrive
rclone mount gdrive: ~/gdrive --vfs-cache-mode writes --daemon
```

```python
DOWNLOAD_DIR = "/home/YOUR_USER/gdrive/telegram_archiver/downloads"
ACCOUNTS_DIR = "/home/YOUR_USER/gdrive/telegram_archiver/accounts"
```

در ابتدای اجرا، فضای آزاد مسیر `DOWNLOAD_DIR` چاپ می‌شود تا مطمئن شوید ماونت واقعاً فعال است.

## 🚧 محدودیت‌ها

- تلگرام برای **گروه‌های ساده** تاپیک ندارد؛ اگر مبدأ گروه ساده باشد، یک سوپرگروه معمولی (بدون تاپیک) ساخته می‌شود.
- ساخت تعداد زیادی تاپیک پشت سر هم ممکن است به محدودیت فلاد بخورد؛ بین هر تاپیک یک مکث کوتاه گذاشته شده است.
- در چت‌هایی که **«محدودیت ذخیرهٔ محتوا»** فعال است، ارسال با رفرنس کار نمی‌کند؛ اسکریپت این را از ابتدا تشخیص می‌دهد.
- سقف حجم آپلود به اکانت بستگی دارد: **2 گیگابایت** عادی و **4 گیگابایت** با تلگرام پرمیوم (خودکار تشخیص داده می‌شود).
- اگر چت مقصد بدون داشتن `progress.json` دوباره استفاده شود، اسکریپت نمی‌داند قبلاً تا کجا پیش رفته و از اول شروع می‌کند (احتمال پیام تکراری).

## ⚖️ قانون و حریم خصوصی

این ابزار دقیقاً مانند **کلاینت شخصی خود شما** و از طریق API رسمی MTProto کار می‌کند. فقط برای چت‌هایی استفاده کنید که اجازهٔ آرشیو کردنشان را دارید و به [قوانین تلگرام](https://telegram.org/tos) و حریم خصوصی بقیهٔ اعضا احترام بگذارید. فایل‌های `*.session` دسترسی کامل به اکانت شما می‌دهند — مثل رمز عبور با آن‌ها برخورد کنید.
