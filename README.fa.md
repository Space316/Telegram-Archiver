**کل یک گروه یا کانال تلگرام — از اولین پیام تا آخرین — را در یک گروه یا کانال جدید روی اکانت خودتان کپی کنید.**

## 📖 این پروژه چه کاری انجام می‌دهد؟

یک ابزار ترمینالی ساده است؛ فقط یک فایل پایتون به اسم `telegram_archiver.py` که روی [Telethon](https://docs.telethon.dev/) نوشته شده. لازم نیست هیچ دستوری حفظ کنید — اجرایش می‌کنید و بقیهٔ کار از داخل منوها پیش می‌رود.

با **اکانت شخصی خودتان** وارد می‌شود (نه ربات)، فهرست گروه‌ها و کانال‌هایتان را نشان می‌دهد، یک گروه یا کانال جدید با همان نام و همان نوع می‌سازد و بعد کل پیام‌ها را یکی‌یکی و به همان ترتیب اصلی داخلش کپی می‌کند. آخر کار یک آرشیو تمیز دارید که انگار از روز اول همان‌جا بوده.

کجا به درد می‌خورد؟ وقتی نگرانید روزی دسترسی‌تان به یک گروه یا کانال قطع شود، وقتی می‌خواهید محتوای یک گروه را به جای تازه‌ای منتقل کنید، یا وقتی یک گروه بزرگ تاپیک‌دار دارید و می‌خواهید بی‌عجله و تاپیک به تاپیک آرشیوش کنید.

<details>
<summary><b>تازه‌کارید؟ آن دو خط venv اصلا برای چیست؟</b></summary>

خط اول یک نسخهٔ جدا و مستقل از پایتون را در پوشه‌ای مخفی به نام `.venv` **داخل خود پوشهٔ پروژه** می‌سازد؛ هیچ جای دیگری از سیستم شما دست نمی‌خورد. خط دوم هم به ترمینال می‌گوید از این به بعد از همان پایتون استفاده کن.

فایده‌اش این است که هر چیزی با `pip` نصب کنید داخل همان پوشه می‌نشیند و نه روی پایتون سیستم، پس این پروژه هیچ‌وقت پروژهٔ دیگری را خراب نمی‌کند. ضمنا بعضی توزیع‌های لینوکس اصلا اجازهٔ نصب سراسری نمی‌دهند و خطای `externally-managed-environment` می‌دهند؛ آنجا این کار عملا تنها راه است.

فعال کردن این محیط دائمی نیست و فقط روی همان پنجره‌ای که دستور را در آن زده‌اید اثر دارد؛ `PATH` سیستم را هم برای همیشه تغییر نمی‌دهد. وقتی فعال باشد، ابتدای خط ترمینال `(.venv)` می‌بینید. در هر ترمینال تازه باید قبل از اجرای اسکریپت دوباره خط activate را بزنید.

پشیمان شدید؟ کافی است پوشهٔ `.venv` را پاک کنید؛ به همین سادگی همه‌چیز به حالت اول برمی‌گردد. این پوشه در `.gitignore` هم هست، پس هیچ‌وقت سر از گیت‌هاب درنمی‌آورد.

در کل این مرحله اختیاری است — اگر حوصله‌اش را ندارید، فقط `pip install -r requirements.txt` هم کار می‌کند.

## 🔑 گرفتن API ID و API HASH

1. به نشانی **https://my.telegram.org** بروید و با شمارهٔ موبایلتان وارد شوید
2. بخش **API development tools** را باز کنید و یک اپ بسازید (اسمش هرچه باشد فرقی نمی‌کند)
3. مقادیر `api_id` و `api_hash` را بردارید

حالا به **یکی** از این سه روش واردشان کنید؛ اسکریپت به همین ترتیب دنبالشان می‌گردد و اولین موردی که پیدا کند برنده است:

</div>

```bash
# 1) متغیرهای محیطی
export TG_API_ID=123456
export TG_API_HASH=abcdef0123456789abcdef0123456789
```

```bash
# 2) فایل config.py کنار اسکریپت (روش معمول)
cp config.example.py config.py
nano config.py
```

<div dir="rtl" align="right">

> 3) یا اصلا کاری نکنید و فقط اسکریپت را اجرا کنید — در اجرای اول خودش می‌پرسد و پیشنهاد می‌دهد یک `config.py` خصوصی (با دسترسی 600) برایتان بسازد. راحت‌ترین راه همین است.

> ⚠️ **فایل `config.py` عمدا در `.gitignore` گذاشته شده. حواستان باشد این فایل و فایل‌های `*.session` را هیچ‌وقت کامیت نکنید.**

## ▶️ نحوهٔ اجرا

</div>

```bash
python3 telegram_archiver.py
```

<div dir="rtl" align="right">

روی ویندوز به جای آن `py telegram_archiver.py` را بزنید.

همین یک دستور، تمام. هیچ فلگ و آرگومان خط فرمانی در کار نیست؛ همه‌چیز از داخل منوها انتخاب می‌شود و شما فقط به سؤال‌ها جواب می‌دهید.

### اجرای اول

اول یک **نام برای این اکانت** می‌خواهد (هر برچسبی که دوست دارید، مثلا `main`)، بعد **شمارهٔ موبایل**، **کد ورودی** که تلگرام می‌فرستد و اگر رمز دومرحله‌ای دارید آن را هم می‌پرسد. سشن در `accounts/<name>.session` ذخیره می‌شود، پس از دفعهٔ بعد دیگر خبری از این سؤال‌ها نیست و یک‌راست وارد منو می‌شوید.

درست قبل از منو هم خلاصهٔ تنظیمات و فضای آزاد دیسک در مسیر `DOWNLOAD_DIR` چاپ می‌شود؛ برای اینکه مطمئن شوید درایو ماونت‌شده واقعا سر جایش است خیلی به درد می‌خورد.

### منوی اصلی

</div>

```
◆ M A I N   M E N U ◆
        account main

» 📦  Pick a group/channel to copy
  👤  Copy only one person's messages from a topic
  🔁  Retry failed messages
  🧹  Reset a chat's progress
  🔄  Switch account
  ❌  Exit
```

<div dir="rtl" align="right">

آن چیزی که روبه‌روی `account` می‌بینید فقط همان نامی است که خودتان در اجرای اول برای اکانت انتخاب کرده‌اید.

با کلیدهای ↑ ↓ حرکت کنید و با **Enter** انتخاب. تقریبا هر صفحه یک گزینهٔ **⬅ Back** هم دارد که فقط یک سؤال به عقب برمی‌گردد؛ نگران نباشید، کل کار را لغو نمی‌کند.

| گزینه | چه کاری می‌کند | چه وقت به کار می‌آید |
|---|---|---|
| 📦 **Pick a group/channel to copy** | حالت عادی و آرشیو کامل. گروه یا کانال مقصد را می‌سازد و کل تاریخچه (یا تاپیک‌های انتخابی) را کپی می‌کند | نقطهٔ شروع اصلی؛ اگر شک دارید همین را بزنید |
| 👤 **Copy only one person's messages from a topic** | مثل بالا، ولی فقط پیام‌های **یک نفر**. در فهرست، کنار همهٔ اعضا یک گزینهٔ ویژهٔ *🎭 Anonymous admin* هم هست برای پیام‌هایی که به اسم خود گروه فرستاده شده‌اند | وقتی می‌خواهید پست‌های یک نفر را جدا کنید، مثلا نویسندهٔ اطلاعیه‌ها |
| 🔁 **Retry failed messages** | فقط سراغ پیام‌هایی می‌رود که قبلا نرسیده‌اند (در `progress.json` ثبت شده‌اند)؛ محافظت ضد تکرار هم روشن است | وقتی کار تمام شده ولی چند پیام جا مانده |
| 🧹 **Reset a chat's progress** | رکورد پیشرفت آن چت را پاک می‌کند تا دفعهٔ بعد از صفر و با **یک مقصد جدید** شروع شود. نگران نباشید، گروه یا کانال قبلی حذف نمی‌شود | وقتی یک اجرا خراب شده و می‌خواهید از نو و تمیز شروع کنید |
| 🔄 **Switch account** | برمی‌گردید به صفحهٔ انتخاب اکانت؛ هر اکانت سشن و `progress.json` خودش را دارد | وقتی می‌خواهید با یک اکانت دیگر آرشیو بگیرید |
| ❌ **Exit** | اتصال را تمیز می‌بندد و بیرون می‌آید | کارتان تمام شد |

### سؤال‌هایی که موقع کپی پرسیده می‌شود

**۱. کدام گروه یا کانال؟** — یک فهرست قابل جستجو؛ کافی است چند حرف تایپ کنید تا فیلتر شود. بعد از انتخاب، خلاصه‌ای از آن چت چاپ می‌شود: فروم هست یا نه، محدودیت ذخیرهٔ محتوا دارد یا نه، و چند پیام سنجاق‌شده در آن هست.

**۲. کدام تاپیک‌ها؟** *(فقط برای فروم‌ها)* — یا **همهٔ تاپیک‌ها**، یا یک فهرست چندانتخابی که هرکدام را خواستید تیک می‌زنید. تعداد پیام هر تاپیک هم کنار نامش نوشته شده تا راحت‌تر تصمیم بگیرید.

**۳. چقدرش کپی شود؟**

| گزینه | یعنی چه |
|---|---|
| 📚 **Everything (full history)** | از اولین پیام تا آخرین |
| 🔢 **Only the most recent messages** | یک عدد می‌پرسد، مثلا `200`. اگر چند تاپیک انتخاب کرده باشید، یعنی N پیام آخر **از هر تاپیک** |

**۴. از کجا شروع شود؟**

| گزینه | یعنی چه |
|---|---|
| ⏮ **From the beginning (or where it stopped last time)** | حالت عادی؛ اگر قبلا کار نیمه‌کاره مانده باشد خودش ادامه می‌دهد |
| 🔗 **From a specific message — paste its link** | در تلگرام روی پیام راست‌کلیک یا لمس طولانی کنید ← *Copy Message Link*. لینک‌های خصوصی `t.me/c/...` و حتی خود آیدی پیام هم قبول است. پیامی که انتخاب کرده‌اید به شکل پیش‌نمایش نشانتان داده می‌شود تا اگر لینک اشتباه بود همان‌جا بفهمید |

**۵. نام فرستنده ابتدای هر پیام اضافه شود؟** — اگر `Yes` بزنید، نام فرستندهٔ اصلی در خط اول و به صورت **بولد** می‌آید (مثل `«علی»`). برای آرشیو تاپیک‌ها واقعا به کار می‌آید، چون در غیر این صورت همهٔ پیام‌ها به اسم شما دیده می‌شوند. اگر چند تاپیک انتخاب کرده باشید، می‌توانید برای هرکدام جداگانه تصمیم بگیرید.

بعد از این سؤال‌ها کپی شروع می‌شود؛ با یک نوار پیشرفت زنده برای هر فایل و شمارنده‌ای مثل `✔ 1,240 copied so far (album of 3, id=90218)`.

### اگر وسط کار قطع شد

پیشرفت مدام در `progress.json` ذخیره می‌شود (به صورت atomic و همراه یک نسخهٔ پشتیبان `.bak`). پس اگر کار نصفه ماند — Ctrl+C زدید، اینترنت رفت، لپ‌تاپ خوابید — کافی است دوباره اسکریپت را اجرا و همان چت را انتخاب کنید. از پیام بعدی ادامه می‌دهد و یادش هم هست هر پیام قدیمی به کدام پیام جدید تبدیل شده، پس ریپلای‌ها بین اجراهای مختلف هم سالم می‌مانند.

## 🖥 اجرای طولانی با tmux (روی سرور حتما)

**مشکل کجاست؟** وقتی اسکریپت را از راه SSH اجرا می‌کنید، اجرای آن به همان پنجرهٔ ترمینال گره خورده است. هر لحظه که اتصال SSH قطع شود — اینترنت پرید، لپ‌تاپ خوابید، پنجره را بستید — اجرا هم با آن تمام می‌شود. آرشیو کامل یک گروه بزرگ ممکن است ساعت‌ها طول بکشد، پس این اتفاق بیشتر از آنچه فکر کنید می‌افتد.

**راه‌حل:** ابزار `tmux` یک ترمینال را **روی خود سرور** زنده نگه می‌دارد. هر وقت خواستید به آن وصل می‌شوید و اوضاع را می‌بینید، جدا می‌شوید تا در پس‌زمینه ادامه بدهد، و بعدا حتی از یک کامپیوتر دیگر دوباره سر می‌زنید. در تمام این مدت اسکریپت دارد کارش را می‌کند.

راه‌حل‌های کلاسیک `nohup` و `&` اینجا به درد نمی‌خورند، چون این ابزار تعاملی است و برای منوهایش به یک ترمینال واقعی احتیاج دارد.

### نصب

</div>

```bash
sudo apt install tmux        # Debian / Ubuntu
sudo dnf install tmux        # Fedora
brew install tmux            # macOS
```

<div dir="rtl" align="right">

### طرز استفاده

</div>

```bash
# 1) یک سشن نام‌دار بسازید
tmux new -s archiver

# 2) داخل آن، اسکریپت را مثل همیشه اجرا کنید
cd ~/Telegram-Archiver
source .venv/bin/activate
python3 telegram_archiver.py

# 3) برای رها کردن در حال اجرا:  Ctrl+b  و بعد  d

# 4) بازگشت در هر زمان دیگر
tmux attach -t archiver
```

<div dir="rtl" align="right">

### چند دستوری که خوب است بلد باشید

| دستور / کلید | کارکرد |
|---|---|
| `tmux new -s archiver` | ساخت سشنی به نام `archiver` |
| **`Ctrl+b`** و بعد **`d`** | **جدا شدن (detach)** — همه‌چیز در پس‌زمینه ادامه پیدا می‌کند |
| `tmux attach -t archiver` | برگشتن به همان سشن |
| `tmux ls` | ببینید چه سشن‌هایی در حال اجرا هستند |
| **`Ctrl+b`** و بعد **`[`** | حالت اسکرول — با ↑ ↓ و PageUp لاگ قبلی را بخوانید؛ با `q` بیرون بیایید |
| `tmux kill-session -t archiver` | حذف سشن (اسکریپت هم متوقف می‌شود) |

> 💡 در tmux کلید `Ctrl+b` نقش «پیشوند» را دارد: اول آن را می‌زنید و رها می‌کنید، *بعد* کلید دوم را — با هم نگه نمی‌دارید.

> ⚠️ برای جدا شدن حتما `Ctrl+b` و بعد `d`. اگر اشتباهی **`Ctrl+c`** بزنید خود اسکریپت متوقف می‌شود — البته فاجعه نیست، به لطف `progress.json` دوباره که اجرایش کنید از همان جا ادامه می‌دهد.

## 🎛 تنظیمات قابل تغییر

همهٔ تنظیمات بالای فایل `telegram_archiver.py` و زیر بخش `# ------------------ settings ------------------` جمع شده‌اند. پیش‌فرض‌ها برای اکثر آدم‌ها خوب کار می‌کنند، ولی اگر خواستید دستکاری کنید اینها هستند:

| تنظیم | پیش‌فرض | توضیح |
|---|---|---|
| `ADAPTIVE_DELAY` | `True` | تا وقتی تلگرام اعتراضی ندارد سریع‌تر می‌رود و با FloodWait خودش را جمع می‌کند |
| `MIN_MESSAGE_DELAY` / `MAX_MESSAGE_DELAY` | `0.3` / `15.0` | کمترین و بیشترین مکث بین پیام‌ها |
| `FAST_TRANSFER` | `True` | دانلود و آپلود چندتکه‌ای |
| `TRANSFER_CONNECTIONS` | `8` | تعداد اتصال موازی هر فایل (بین 4 تا 16 منطقی است؛ بیشتر از آن یعنی FloodWait) |
| `PREFER_DIRECT_MEDIA` | `True` | ارسال مدیا با رفرنس به جای دانلود + آپلود |
| `MIN_FREE_DISK_GB` | `3` | اگر فضای آزاد از این کمتر شد، دیگر دانلود نمی‌کند |
| `MAX_FILE_SIZE_GB` | `None` | از فایل‌های بزرگ‌تر از این رد می‌شود (`None` یعنی بدون محدودیت) |
| `SPLIT_LONG_TEXT` | `True` | متن‌های بالای 4096 کاراکتر به جای بریده شدن، در ادامه فرستاده می‌شوند |
| `VERIFY_SENT` | `"media"` | `always` / `media` / `never` — چک کردن اینکه پیام واقعا رسیده |
| `DOWNLOAD_DIR` و `ACCOUNTS_DIR` | `downloads` و `accounts` | محل فایل‌های موقت و سشن‌ها |

<details>
<summary><b>💾 فضای دیسک سرور کم است؟ گوگل درایو را با rclone ماونت کنید</b></summary>

اسکریپت هر فایل موقت را بلافاصله بعد از آپلود پاک می‌کند، پس در هر لحظه فقط به اندازهٔ **یک** فایل جا لازم دارد. اگر همین هم برایتان زیاد است:

</div>

```bash
curl https://rclone.org/install.sh | sudo bash
rclone config                      # یک remote مثلا به نام gdrive بسازید
mkdir -p ~/gdrive
rclone mount gdrive: ~/gdrive --vfs-cache-mode writes --daemon
```

```python
DOWNLOAD_DIR = "/home/YOUR_USER/gdrive/telegram_archiver/downloads"
ACCOUNTS_DIR = "/home/YOUR_USER/gdrive/telegram_archiver/accounts"
```

موقع اجرا فضای آزاد مسیر `DOWNLOAD_DIR` چاپ می‌شود، پس همان‌جا می‌فهمید ماونت واقعا گرفته یا نه.

## 🚧 محدودیت‌ها

چند چیز هست که بهتر است از قبل بدانید تا غافلگیر نشوید:

- تلگرام در **گروه‌های ساده (basic group)** تاپیک ندارد؛ اگر گروه اصلی از این نوع باشد، به جایش یک سوپرگروه معمولی بدون تاپیک ساخته می‌شود.
- ساختن تعداد زیادی تاپیک پشت سر هم ممکن است به محدودیت تلگرام بخورد، برای همین بین هرکدام کمی مکث گذاشته شده.
- در چت‌هایی که **«محدودیت ذخیرهٔ محتوا»** روشن است، ارسال با رفرنس ممکن نیست؛ اسکریپت این را از اول تشخیص می‌دهد و تا جایی که بشود سراغ دانلود و آپلود دوباره می‌رود.
- سقف حجم آپلود به اکانت شما بستگی دارد: **۲ گیگابایت** به صورت عادی و **۴ گیگابایت** با تلگرام پرمیوم (خودکار تشخیص داده می‌شود).
- اگر از یک مقصد قبلی استفاده شود ولی `progress.json` متناظرش موجود نباشد، اسکریپت نمی‌داند اجرای قبلی تا کجا رفته و از اول شروع می‌کند — که ممکن است پیام تکراری بسازد.

## 🧯 اگر به مشکل خوردید

| نشانه | راه‌حل |
|---|---|
| سرعت انتقال حدود 1MB/s گیر کرده | `pip install cryptg` |
| نام‌های فارسی برعکس نمایش داده می‌شوند | `pip install arabic-reshaper python-bidi` |
| مدام `FloodWaitError` می‌گیرید | مقدار `TRANSFER_CONNECTIONS` را کم و `MIN_MESSAGE_DELAY` را زیاد کنید |
| پیام `Please install these two libraries first` | `pip install rich questionary` |
| دستور `source` روی ویندوز شناخته نمی‌شود | از بلوک PowerShell بالا استفاده کنید: `.venv\\Scripts\\Activate.ps1` |
| فضای دیسک تمام شد | `MIN_FREE_DISK_GB` را بالا ببرید، برای `MAX_FILE_SIZE_GB` مقدار بگذارید یا سراغ rclone بروید |
| با قطع شدن SSH اجرا هم می‌میرد | از tmux استفاده کنید (بخش بالا) |
| چند پیام نرسیده‌اند | منوی اصلی ← **Retry failed messages** |
| یک اجرا هیچ پیامی کپی نکرد | منوی اصلی ← **Reset a chat's progress** و بعد دوباره امتحان کنید |

## ⚖️ قانون و حریم خصوصی

این ابزار همانند **کلاینت شخصی خود شما** و از طریق API رسمی MTProto عمل می‌کند. مسئولیت نحوهٔ استفاده از این ابزار و هرگونه استفادهٔ نادرست از آن، تنها بر عهدهٔ خود کاربر است. توجه داشته باشید که فایل‌های `*.session` دسترسی کامل به اکانت شما را فراهم می‌کنند، بنابراین آن‌ها را همانند رمز عبور محرمانه نگه دارید.
